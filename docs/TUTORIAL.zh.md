## 🚀 快速入门与 API 密钥配置

   - 选择对应的服务商（**Google Gemini AI** 或 **Anthropic Claude**）。
   - 选择您要使用的模型：
     * **Google Gemini 模型**：
       - `gemini-3.5-flash` (最新快速) — 输入: $0.075 / 1M, 输出: $0.30 / 1M.
       - `gemini-2.5-flash` (默认快速且性价比高) — 输入: $0.075 / 1M, 输出: $0.30 / 1M.
       - `gemini-2.5-pro` (高智能推理) — 输入: $1.25 / 1M, 输出: $5.00 / 1M.
       - `gemini-1.5-flash` (旧版快速) — 输入: $0.075 / 1M, 输出: $0.30 / 1M.
       - `gemini-1.5-pro` (旧版高智能) — 输入: $1.25 / 1M, 输出: $5.00 / 1M.
       - `gemini-2.0-flash-exp` (预览版实验) — 输入: $0.075 / 1M, 输出: $0.30 / 1M.
     * **Anthropic Claude 模型**：

## ⚠️ 使用 `.understandignore` 控制成本（至关重要）

由于分析的第二阶段 (Phase 2) 会使用大模型逐个阅读代码文件的文本内容，如果直接对体积庞大的第三方依赖目录、打包产物或二进制文件运行分析，将会导致您的 API Token 消耗激增。**为了防止高昂的账单支出，您必须配置忽略规则。**

### 什么是忽略文件？
`.understandignore` 是一个位于您项目文件夹内以下位置的纯文本文件：
`[您的项目文件夹]/.understand-anything/.understandignore`

> [!IMPORTANT]
> **自动排除项与生成规则**：如果您的项目中不存在此文件，应用程序的后端**将在第一次运行时自动创建它**（在阶段 0.5），并填入高度优化的默认规则（忽略 `node_modules/`、`dist/`、`.git/`、编译产物、日志及锁定文件），以保护您的 API 余额免受意外的巨额扣费。您可以随时自由查看、修改或添加自定义排除路径。

任何在该文件中被匹配到的文件或文件夹模式都将在扫描阶段被完全跳过，**绝不会**被发送给 AI 大模型进行读取。

### 推荐排除的目录与文件
您应该始终排除非核心文件、第三方依赖、构建产物目录以及静态媒体资源：

| 类别 | 常见匹配模式 | 排除原因 |
|---|---|---|
| **包管理器/第三方依赖** | `node_modules/`, `.venv/`, `venv/`, `__pycache__/`, `bower_components/` | 包含成千上万个非您编写的外部库文件。**请务必排除这些文件夹。** |
| **构建/输出目录** | `dist/`, `build/`, `out/`, `target/`, `bin/`, `obj/` | 打包或编译后的代码会重复源文件的逻辑，导致 Token 消耗翻倍。 |
| **版本控制** | `.git/`, `.github/`, `.svn/`, `.hg/` | 包含海量提交记录和历史版本的元数据文件夹。 |
| **锁定文件** | `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `cargo.lock` | 动辄几万行的纯文本依赖树文件，发送给 AI 会造成极大的 Token 浪费。 |
| **媒体与二进制文件** | `*.png`, `*.jpg`, `*.mp4`, `*.zip`, `*.pdf`, `*.mov` | 无法作为源码读取，且会白白占用大模型的上下文窗口限制。 |
| **测试/覆盖率报告** | `coverage/`, `.nyc_output/` | 测试运行产生的临时报告及日志。 |

### 如何编写忽略规则
每行编写一条匹配规则，支持标准的 glob 通配符模式：
- `/node_modules` 或 `node_modules/` 忽略整个依赖文件夹。
- `*.log` 忽略所有的日志文件。
- `temp/*` 忽略临时文件夹下的所有内容。

## 🔄 使用实时忽略编辑器与重新计算

为了让成本控制更加简单，桌面端应用程序在费用确认弹窗中集成了一个实时的 `.understandignore` 编辑器。

> [!TIP]
> **如何在运行中实时优化您的分析预算：**
> 1. 选择您的项目文件夹，然后点击 **Analisar Repositório**（分析代码库）。
> 2. 软件会执行快速的本地离线扫描，并弹出 **Confirmar Estimativa de Custo**（确认费用估算）对话框。
> 3. 查看 **Estimated AI API Cost**（估算费用）。如果费用超出了您的预期：
>    - 在对话框右侧的 **Exclude Rules (.understandignore)** 编辑器中，加入要排除的目录（例如 `node_modules/` 或 `dist/`）。
>    - 点击 **Save & Recalculate**（保存并重新计算）按钮。
> 4. 软件将立即把新规则写入到本地文件中，终止后台当前的管道运行，并重新启动一次全新的离线文件扫描。
> 5. 几秒钟内，更新后（明显降低）的文件数、Token 数和费用预估会重新呈现在您面前！
> 6. 当您对费用感到满意时，点击 **Confirm & Proceed**（确认并继续）开始调用 AI 分析。

## 📊 深入了解 7 阶段分析工作流

软件将按照以下步骤逐步处理您的项目：

1. **阶段 0：Pre-flight**：目录准备与运行环境校验。
2. **阶段 0.5：配置排除项**：检查并生成默认的 `.understandignore` 排除规则。
3. **阶段 1：Varredura do Projeto（项目扫描）**：本地离线扫描所有文件，收集文件大小、语言并提取 import 引用关系。
4. **阶段 1.5：划分批次**：将相关的代码文件智能地打包进不同批次（以保证文件之间的依赖完整性）。
5. **确认费用估算**：*需要用户交互。* 显示预测的 Token 消耗和估算美元（$）费用。
6. **阶段 2：代码分析 (AI)**：核心顺序处理阶段，大模型依次阅读各批次代码，生成概要并分析逻辑依赖。
7. **阶段 3 至 6：图谱合并与连线**：规范化节点 ID，自动将测试文件链接到对应的生产代码，计算逻辑复杂性。
8. **阶段 7：服务部署与看板**：在本地启动安全的 Express 服务，通过嵌入式视窗呈现交互式 看板。

## 🎮 交互式 知识图谱的操作与使用

分析完成后，看板会加载一个互动的 画布：

- **视图导航**：
  - **鼠标左键 + 拖拽**：旋转 画布。
  - **鼠标右键 + 拖拽（或 Shift + 拖拽）**：平移摄像机（Pan）。
  - **鼠标滚轮**：放大和缩小视图。
- **节点分类**：
  - 节点代表代码中的不同元素（文件、函数、类、路由/接口端点）。
  - 将鼠标悬停在节点上可查看其物理路径、语言类型、语义摘要和复杂性级别。
- **代码复杂性评估**：
  - **绿色 (Simple)**：代码行数少，逻辑清晰直接。
  - **黄色 (Moderate)**：中等复杂程度及依赖关系。
  - **红色 (Complex)**：高度耦合或包含极为复杂的逻辑。这些红色节点是进行代码重构的最佳目标！
- **历史最近项目**：
  - 设置屏幕会列出您最近分析过的 5 个项目。点击它们可以在 1 秒内瞬间加载出 图谱，无需重复分析，也不产生任何 AI 费用。
