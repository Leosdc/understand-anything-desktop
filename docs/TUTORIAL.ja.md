## ⚠️ `.understandignore` によるコスト管理（極めて重要）

フェーズ 2 では LLM がコードファイルの実際のテキスト内容を読み取るため、巨大なサードパーティの依存関係フォルダ、ビルド成果物、またはバイナリアセットに対してアナライザーを実行すると、API トークンの消費量が急速に増加します。**不要な出費を避けるために、除外ルールを設定することが必須です。**

### 除外（Ignore）ファイルとは？
`.understandignore` は、プロジェクトフォルダ内の以下の場所に配置される純テキストファイルです：
`[プロジェクトフォルダ]/.understand-anything/.understandignore`

> [!IMPORTANT]
> **自動除外と自動生成ルール**: もしこのファイルがリポジトリ内に存在しない場合、アプリケーションのバックエンドは**最初の実行時に自動的にこのファイルを生成します**（フェーズ 0.5 の間）。その際、ウォレットを保護するために、あらかじめ最適化されたデフォルトのルール（`node_modules/`, `dist/`, `.git/`, ビルドディレクトリ、ログ、ロックファイル等）が自動で書き込まれます。その後、いつでも自由に内容を確認し、追加編集することができます。

このファイルに記述されたパターンに一致するファイルやフォルダは、スキャンフェーズで完全にスキップされ、AI モデルに送信されることは**ありません**。

### 推奨される除外対象
ソースコードではないファイル、サードパーティのライブラリ、コンパイル成果物、および静的メディアは常に除外してください。

| カテゴリ | パターン例 | 除外する理由 |
|---|---|---|
| **パッケージマネージャー** | `node_modules/`, `.venv/`, `venv/`, `__pycache__/`, `bower_components/` | 数万の外部ライブラリファイルが含まれています。**これらは絶対に分析しないでください。** |
| **ビルド / 出力成果物** | `dist/`, `build/`, `out/`, `target/`, `bin/`, `obj/` | コンパイル・パッケージ化されたコードは、元のソースコードロジックを重複して格納しているため、トークン消費が倍増します。 |
| **バージョン管理** | `.git/`, `.github/`, `.svn/`, `.hg/` | 膨大な履歴ログを含むメタデータフォルダです。 |
| **ロックファイル** | `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `cargo.lock` | 依存関係パスが並ぶ巨大なテキストファイルであり、AI に読み込ませるとトークンの無駄になります。 |
| **メディアとバイナリ** | `*.png`, `*.jpg`, `*.mp4`, `*.zip`, `*.pdf`, `*.mov` | ソースコードとして解釈できず、AI のコンテキストウィンドウ制限を浪費します。 |
| **テスト / カバレッジ** | `coverage/`, `.nyc_output/` | テストツールが生成する一時的なレポートやログ。 |

### 除外ルールの書き方
1 行に 1 つのパターンを記述します。標準的な glob パターンがサポートされています。
- `/node_modules` または `node_modules/` はフォルダ全体を無視します。
- `*.log` はすべてのログファイルを無視します。
- `temp/*` は一時フォルダ内のすべてのファイルを無視します。

## 🔄 リアルタイム除外エディターと再計算の使用方法

コスト管理をより簡単にするため、デスクトップアプリにはコスト確認画面内に直接編集できる `.understandignore` エディターが搭載されています。

> [!TIP]
> **予算をその場で最適化するステップ：**
> 1. 対象のプロジェクトフォルダを選択し、**Analisar Repositório**（分析実行）をクリックします。
> 2. アプリは高速なローカルオフラインスキャンを実行し、**Confirmar Estimativa de Custo**（コスト見積もり確認）ダイアログを表示します。
> 3. **Estimated AI API Cost**（見積もりコスト）を確認します。もし高すぎる場合は：
>    - ダイアログ右側の **Exclude Rules (.understandignore)** エディターに、除外したいディレクトリ（例: `node_modules/` や `dist/`）を入力します。
>    - **Save & Recalculate**（保存して再計算）ボタンをクリックします。
> 4. アプリは変更内容をローカルファイルに保存し、現在の分析処理をキャンセルして、即座に新しいスキャンを最初から実行します。
> 5. 数秒後、削減されたファイル数とトークン数に基づく新しいコスト見積もりが再表示されます！
> 6. コストに納得できたら、**Confirm & Proceed**（確認して続行）をクリックして AI 分析を開始します。

## 📊 7 フェーズの分析パイプラインを理解する

アプリがプロジェクトを処理する各ステップは以下の通りです：

1. **フェーズ 0: Pre-flight**: ディレクトリの作成と実行環境の検証。
2. **フェーズ 0.5: 除外ルールの構成**: デフォルトの `.understandignore` 構成を確認し、存在しない場合は生成します。
3. **フェーズ 1: Varredura do Projeto（プロジェクトスキャン）**: ローカルでファイルを走査し、サイズ、言語、および import 参照関係をオフラインで解析します。
4. **フェーズ 1.5: セマンティックバッチ分割**: 関連するファイルをインテリジェントにバッチへ分割します（ファイルの依存関係をまとめるため）。
5. **コスト見積もり確認**: *ユーザーの操作が必要。* 予測されるトークン消費量と米ドル（$）コストを表示します。
6. **フェーズ 2: コード分析 (AI)**: LLM が各バッチのコードを読み取り、概要を作成して論理的な依存関係を順次検出します。
7. **フェーズ 3 〜 6: 統合と接続**: ノード ID を標準化し、テストファイルを該当する生産ファイルに紐付け、論理複雑度を計算します。
8. **フェーズ 7: サーバー起動とダッシュボード表示**: ローカルで安全な Express サーバーを起動し、インタラクティブな ダッシュボードを表示します。

## 🎮 知識グラフの操作方法

分析が完了すると、インタラクティブな ダッシュボードが読み込まれます：

- **ビューの操作**:
  - **マウス左ボタン + ドラッグ**: キャンバスの回転。
  - **マウス右ボタン + ドラッグ（または Shift + ドラッグ）**: カメラの並行移動（Pan）。
  - **マウスホイール**: ズームイン・ズームアウト。
- **ノードの分類**:
  - ノードはコードの要素（ファイル、関数、クラス、ルート/エンドポイント）を表します。
  - ノードにカーソルを合わせると、ファイルパス、言語、セマンティック概要、および複雑度レベルが表示されます。
- **コードの複雑度**:
  - **緑色 (Simple)**: コード行数が少なく、ロジックがシンプルです。
  - **黄色 (Moderate)**: 平均的な複雑度と依存関係を持っています。
  - **赤色 (Complex)**: 結合度が高く、複雑なロジックを含みます。リファクタリングを検討する最適な対象です！
- **履歴プロジェクト**:
  - 設定画面には、最近分析した 5 つのプロジェクトが履歴として表示されます。クリックすると、AI への再問い合わせをすることなく、1 秒で グラフが読み込まれます。
